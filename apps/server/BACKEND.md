# apps/server + packages/db: back-end guide

A Hono API that serves **exactly** the contracts of `@was/shared` (`packages/shared/src/contracts/*.contract.ts`) on
Postgres through Drizzle (embedded PGlite by default). Business rules, schemas, enums and messages come **only** from
the shared package: the server applies them and never redefines them. The same process also renders the pages (SSR).

Code conventions: [`docs/engineering/conventions.md`](../../docs/engineering/conventions.md). Package map and
layering: [`docs/engineering/architecture.md`](../../docs/engineering/architecture.md). Tools:
[`docs/engineering/tooling.md`](../../docs/engineering/tooling.md).

## Layout

```
packages/db/src/                       @was/db
  columns/base.column.ts               baseColumns() (uuid v7, created/updated/deleted at/by, created_via, version) + live() for partial indexes
  columns/pg-enum.column.ts            pgEnums built from the shared *_VALUES
  tables/*.table.ts                    one aggregate per file (table + its *_translations)
  repositories/base.repository.ts      BaseRepository, the ONLY writer: insert/update/softDelete/restore/ensure/increment/audit/transaction
  repositories/base-read.repository.ts BaseReadRepository: selectRows, active(), pageWindow()
  cli/base.cli.ts                      BaseCli (env, database, migrate, args, exit code); migrate/seed/reset/cleanup CLIs
  migrations/                          generated by drizzle-kit (+ forbid-delete trigger: physical DELETE is blocked)
  seeds/                               configuration, domain vocabulary, prototype data, source policies, sports catalog, sport content
  client.ts                            createDatabase(): node-postgres (DATABASE_URL) or PGlite (.data/pglite | memory://)
apps/server/src/
  main.ts / app.ts                     bootstrap (migrates on boot) / createApp() (tests use app.request)
  routes.const.ts                      ALL_ROUTES (a test asserts every contract is served exactly once)
  core/                                BaseController, BaseService, BaseScheduler, BaseMapper, RequestContext
  http/contract-route.helper.ts        defineRoute(contract, handler) + registerRoutes()
  http/http-error.error.ts             HttpError (body = ApiErrorSchema); factories in http-error.helper.ts
  config/                              env schema (env.const.ts) and ServerConfig (env.config.ts)
  auth/                                AuthProvider: Better Auth (Google) + simulated profiles (dev) via composite.provider.ts
  middlewares/                         error, request log, locale, compress, secure headers, session
  rate-limit/                          rate limiter + store (memory or database)
  modules/<feature>/                   <feature>.route.ts · <feature>.controller.ts · <feature>.service.ts · <feature>.repository.ts
  modules/catalog/                     in-memory catalog snapshot (catalog.cache.ts) + CatalogView (rows → contract views)
  maintenance/cleanup.scheduler.ts     periodic cleanup of expired sessions and rate-limit windows
  web/                                 SSR (web.route.ts), HTML cache, SEO routes, image proxy, slug redirects
  observability/instrumentation.ts     optional OpenTelemetry
```

Request flow: `requestLog → compress → timing → /api/*: secureHeaders → locale → cors → bodyLimit → [/api/auth/* =
Better Auth] → session → route generated from the contract`.

The generated route does, for every endpoint: access rule (`accessDenial` from shared: 401/403/banned) → rate limit
(`RATE_LIMITS` from shared) → `params`/`query`/`body` validated by the contract schemas (422
`{ error, message, errors: { field: msg } }`) → handler → `contract.response.safeParse` (a mismatch is a 500 plus a log,
never a wrong payload).

Layering: route → controller → service → repository. Controllers never touch the database; repositories never know
HTTP. Example: `modules/athletes/athletes.route.ts`:

```ts
defineRoute(PublicApi.athleteProfile, (input, ctx) => new AthletesController(ctx).profile(input)),
```

### Languages (pt-BR, en, es; same URL)
`middlewares/locale.middleware.ts` resolves the language of every `/api` call with `resolveLocale` from shared:
`?locale=` → `x-was-locale` header (the web app sends the current language) → `was_locale` cookie → `Accept-Language`
→ pt-BR. It is stored in `ctx.locale` and sent back in `Content-Language` (+ `Vary: Accept-Language, Cookie,
x-was-locale`). Errors: `HttpError` carries a `messageKey` (a key of `API_ERROR_MESSAGES`) that the error handler
translates; shared validators receive `ctx.locale`, so a 422 already comes in the right language. `CatalogCache` loads
the rows once and builds **one `CatalogView` per language** (text: requested → pt-BR → en → any); `onWrite` clears all
of them. Detail responses expose `contentLocale` (the language the content actually came in).

### Pages (SSR)
On the same server and port: `createApp({ web })` mounts `web/web.route.ts` after the API.
- Production: `/assets/*` from `apps/web/dist/client` with `Cache-Control: immutable`, public files, and every other GET
  goes to `render()` of `dist/server/entry-server.js` (assets from `.vite/manifest.json`, `web/web-assets.helper.ts`).
- Development (`WEB_DEV=1`, `web/vite-dev.helper.ts`): an `http.Server` with Vite's middlewares (modules, HMR) in front
  of Hono; `entry-server.tsx` is loaded with `ssrLoadModule` on every request (edits need no restart).
- The renderer calls the API **in process** (`app.fetch`) with the page's cookies. Those calls carry `x-was-ssr: 1` and
  are logged as `ssr→api GET …` right before the page line. `/api/*` never falls through to SSR (404 JSON).
- Old slugs answer with a 301 (`web/slug-redirect.route.ts`).

**HTML cache** (`web/html.cache.ts`, rules in `web/html-cache.helper.ts` and `web/html-cache.const.ts`): an anonymous
page (no app cookie `was_session`/`was_fixture`/`was-theme`, no Better Auth `was.*` cookie, no `?as=`/`?fixture=`,
outside `/admin` and `/me`, status 200) is sent with `Cache-Control: public, max-age=0, s-maxage=300,
stale-while-revalidate=86400`, a weak `ETag` of the bytes (nonce included) and 304 on `If-None-Match`. In production it
is also kept in an in-process LRU (`SSR_CACHE_TTL_SECONDS`, default 60 s) that is **cleared on writes to tables shown on
public pages** (catalog, comments, reactions, votes: `affectsPublicPages` in the `BaseRepository` `onWrite` hook).
Private writes (users, notifications, contact, suggestions, consents) do not clear it. Everything else is
`private, no-cache` and streamed. Always `Vary: Cookie, Accept-Language, Accept-Encoding` and `Content-Language`. The
language is a **cacheable** variant (part of the LRU key, e.g. `pt-BR|/athletes`), not personal data. A cached page
reuses the nonce stored in its body (the CSP header is built after the handler).

**Compression** (`middlewares/compress.middleware.ts`): brotli (q5) or gzip per chunk for pages, JSON and SEO files;
`/assets` are precompressed at build time (`.br`/`.gz`, `apps/web/scripts/precompress.mjs`).

**Limits**: `/api` bodies up to `BODY_LIMIT_KB` (413), SSR render up to `SSR_TIMEOUT_MS` (503), Postgres pool with
`DB_POOL_MAX` / `DB_STATEMENT_TIMEOUT_MS` / `DB_CONNECTION_TIMEOUT_MS`, HTTP server with `headersTimeout` 15 s and
`requestTimeout` 30 s.

**SEO** (`web/seo.route.ts`, helpers in `@was/shared` `seo/`): `/robots.txt` (blocks `/admin`, `/me`, `/api/` and URLs
with `q=`/`as=`/`fixture=`) and `/sitemap.xml` (index) → `/sitemaps/static.xml`, `/sitemaps/athletes.xml`,
`/sitemaps/sports.xml`, with `lastmod` = catalog `updated_at` (`CatalogView.sitemapEntries()`) and absolute URLs from
`PUBLIC_URL`.

**Split CSP** (`middlewares/secure-headers.middleware.ts`): `/api` gets `default-src 'none'`; pages get a per-request
nonce (`script-src 'self' 'nonce-…'`, `style-src 'self' 'nonce-…'`, `style-src-attr 'unsafe-inline'`, `img-src`
Wikimedia + `lh3.googleusercontent.com`, `font-src 'self'`, `frame-ancestors 'none'`, `base-uri`/`form-action 'self'`).
In development it adds `'unsafe-inline'` for styles, `ws:` and `worker-src blob:` (Vite HMR).

**Catalog reads** (athletes, sports, organizations, calendar…) use an **in-memory snapshot** (`CatalogCache`), cleared
**automatically** by `BaseRepository` (`onWrite` hook, after commit) when any catalog table is written. Participation
data (votes, comments, notifications, inbox, audit) is always read live.

## Adding an endpoint
1. Contract in `packages/shared/src/contracts/*.contract.ts`
   (`defineContract({ method, path, access, params?, query?, body?, response, summary })`) + schemas in
   `packages/shared/src/schemas/`. New business rule → pure helper in `packages/shared/src/helpers/` with a test (the web
   app uses the same one).
2. Service in `modules/<feature>/<feature>.service.ts` extending `BaseService`: rules, reads through a read repository
   (`<feature>.repository.ts` extending `BaseReadRepository`) and writes through `this.repo`.
3. Controller method in `<feature>.controller.ts` extending `BaseController`: takes the validated input, calls
   `this.service(XService)`, returns the contract response. No database access.
4. Route in `<feature>.route.ts`: `defineRoute(Api.x, (input, ctx) => new XController(ctx).x(input), { rateLimit: 'comment' })`.
   `input` is already validated and typed by the contract; `ctx.session.user` exists when `access` is not public.
5. New module → add its route list to `routes.const.ts`. `test/contracts.test.ts` fails when a contract has no route;
   for a GET, add its input to `GET_INPUTS` so the response is validated against the schema.

Writes: `this.repo.insert|update|softDelete(table, …, this.actor, { summary, reason })` (version, `entity_versions` and
`audit_logs` are automatic). Admin decision: `this.audit(…)`. Inside `this.transaction(fn)` use only the `repo` passed to
`fn` (PGlite has one connection: querying `db` inside it deadlocks).

## Database, migrations and seed
| Command | What it does |
|---|---|
| `pnpm db:generate` | `drizzle-kit generate` from `packages/db/src/schema.ts` (a new migration must end with `SELECT protect_all_tables();`) |
| `pnpm db:migrate` | applies the migrations (the server also migrates on boot: `MIGRATE_ON_BOOT=1`) |
| `pnpm db:seed` | migrates + seeds configuration, domain vocabulary, source policies, sports catalog, sport content and the **prototype** data (`plan/front-prototype/mock`, through `scripts/fixtures/prototype-loader.mjs`, the same loader as the fixture exporter). Idempotent: upsert by natural key or deterministic id |
| `pnpm db:reset` | **deletes** `.data/pglite` and runs the seed (never touches `DATABASE_URL`) |
| `pnpm db:cleanup` | removes expired auth sessions/verifications and rate-limit windows (also run by `CleanupScheduler`) |

- The prototype data needs `plan/` (gitignored). Without it only configuration and catalog data are seeded.
- **PGlite is single-process**: stop `pnpm dev` before `db:seed`/`db:migrate`/`pnpm ingest` on the same `.data/pglite`.
- Soft delete only: a physical `DELETE` raises an exception (`forbid_delete` trigger).

## Sign-in (Google through Better Auth) and simulated session
- `auth/better-auth.config.ts` (`better-auth` 1.7.17): Drizzle adapter over `users` (`name→displayName`,
  `image→avatarUrl`) + `auth_sessions`/`auth_accounts`/`auth_verifications` (ephemeral, exempt from `forbid_delete`), uuid
  v7 ids, `was.*` cookies (HttpOnly, Lax, Secure in production), Google only (`prompt: select_account`). Mounted on
  `/api/auth/*` before the session middleware. Hooks: new account → `locale` from the `was_locale` cookie,
  `emailVerifiedAt`, role from `ADMIN_EMAILS`, audit; session → IP stored only as `ip_hash`.
- `AuthProvider` = `auth/composite.provider.ts`: Better Auth (`getSession` → `loadAuthUser` → consent rule) and, only
  with `AUTH_SIMULATED`, the simulated provider (`x-was-session` / `was_session` cookie / `?as=` → demo accounts). Terms
  or Privacy of the current version not accepted = **pending** session (anonymous for access;
  `GET /api/session.pendingConsent`). `POST /api/account/consent` stores terms/privacy/age declaration with `ip_hash`
  (409 `consent_outdated` if the version is not the current one).
- A non-public route with an unverified e-mail → 403 `email_unverified`. Deleting an account deletes its Better Auth
  sessions and accounts. `ADMIN_EMAILS` promotes on boot (idempotent, audited).
- Without `GOOGLE_CLIENT_ID/SECRET` the app starts with a warning; `GET /api/session.googleEnabled=false` and the dialog
  says Google sign-in is not configured.
- **Testing consent without Google**: `pnpm dev:api`, pick a demo reader or `?as=admin`: the local demo accounts were
  seeded with an older Privacy version and get the consent dialog. To repeat: `pnpm db:reset`; to force it again, bump
  the version in `LEGAL_DOCUMENT_VERSIONS`.
- Real Google: Google Cloud Console → OAuth client of type "Web application" with origin `http://localhost:8787` and
  redirect `http://localhost:8787/api/auth/callback/google`; fill in `.env` (see `.env.example`) and restart.

## Environment variables
All optional in development; the root `.env` is loaded on boot (see `.env.example`). Schema:
`apps/server/src/config/env.const.ts`.

| Variable | Default | Use |
|---|---|---|
| `PORT` / `HOST` | `8787` / `127.0.0.1` | server |
| `DATABASE_URL` | — | Postgres (node-postgres); without it, PGlite |
| `PGLITE_DATA_DIR` | `.data/pglite` | PGlite directory (relative to the repo root) or `memory://` |
| `CORS_ORIGINS` | `http://localhost:8787,http://127.0.0.1:8787` | origins accepted on `/api` (pages are same-origin) |
| `IP_HASH_SALT` | `dev-only-salt` | salt of `ip_hash`; **required in production** (16+ characters, different from dev) |
| `RATE_LIMIT_ENABLED` / `LOG_REQUESTS` / `MIGRATE_ON_BOOT` | `1` | on/off switches |
| `RATE_LIMIT_STORE` | `database` in production or with `DATABASE_URL`, else `memory` | rate-limit store |
| `CLEANUP_INTERVAL_MINUTES` | `60` | cleanup scheduler interval (`0` = off) |
| `INGEST_SCHEDULE_MONTHS` | `6` | autonomous collection every N months (`0` = off; production uses `0`) |
| `MIGRATIONS_DIR` | next to the module | migrations folder (the build copies it to `dist/migrations`) |
| `WEB_DEV` | `0` (`pnpm dev` sets `1`) | Vite in middleware mode in the same process (SSR + HMR) |
| `WEB_DIST_DIR` | `apps/web/dist` | web build (`client/` + `server/entry-server.js`); without it, API only (warning on boot) |
| `APP_TIME_ZONE` | `America/Sao_Paulo` | "today" of the pages (calendar, on this day, ages) |
| `PUBLIC_URL` | `http://localhost:<PORT>` | origin of canonical/og links, JSON-LD, sitemap and robots |
| `BETTER_AUTH_URL` | `PUBLIC_URL` | Better Auth origin (Google callback = `<url>/api/auth/callback/google`) |
| `BETTER_AUTH_SECRET` | fixed dev value | 32+ characters; **required in production** (with or without Google) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | — | Google OAuth (both, or sign-in stays off) |
| `ADMIN_EMAILS` | — | e-mails promoted to admin (on boot and on first sign-in) |
| `AUTH_SIMULATED` | `1` outside production | demo profiles (`x-was-session`); forbidden in production (boot fails) |
| `SSR_CACHE_TTL_SECONDS` | `60` | production: TTL of the in-process anonymous HTML cache (`0` = off; never used in dev) |
| `SSR_TIMEOUT_MS` / `BODY_LIMIT_KB` | `10000` / `64` | slower renders answer 503; larger `/api` bodies answer 413 |
| `IMAGE_PROXY_TIMEOUT_MS` / `IMAGE_PROXY_CACHE_MB` | `8000` / `64` | image proxy upstream timeout and byte-sized LRU |
| `DB_POOL_MAX` / `DB_STATEMENT_TIMEOUT_MS` / `DB_CONNECTION_TIMEOUT_MS` | `10` / `10000` / `5000` | Postgres pool per process (ignored with PGlite) |
| `LOG_FORMAT` / `SLOW_REQUEST_MS` | `json` in production, `text` in dev / `1000` | request log format; slower requests become `warn` (even with `LOG_REQUESTS=0`) |
| `OTEL_EXPORTER_OTLP_ENDPOINT` (+ standard `OTEL_*`) | — | enables OpenTelemetry (HTTP spans and one span per Postgres query); `OTEL_TRACES_EXPORTER=console` prints to the terminal |
| Web: `VITE_DATA_SOURCE=http` | fixtures | pages read the real API (dev and build) |

Ingestion-only variables (`OLLAMA_URL`, `OLLAMA_MODEL`, …) are read by `packages/ingest`, not by the server.

## Running and testing
Everything on http://localhost:8787: `pnpm dev:api` (pages with the real API) · `pnpm dev` (pages with fixtures) ·
`pnpm --filter server test` (in-memory PGlite: conformance of every GET, mutation rules, pages/CSP in
`src/test/web.test.ts`) · `pnpm build && pnpm start` (`NODE_ENV=production node --import
./apps/server/dist/instrumentation.js apps/server/dist/main.js`; for real data: `VITE_DATA_SOURCE=http pnpm build`;
requires `IP_HASH_SALT` and `BETTER_AUTH_SECRET`). Rankings CLI: `pnpm rankings:calculate` (`src/cli/rankings.cli.ts`).

## Docker image
- Root `Dockerfile` (multi-stage, `node:26-slim` pinned by digest): `pnpm fetch` + offline install → `pnpm build` with
  `VITE_DATA_SOURCE=http` → `pnpm --filter server deploy --prod --legacy /out` (pnpm 10+ needs `--legacy` without
  `inject-workspace-packages`; the `@was/*` packages are bundled into `main.js`).
- Runtime in `/app`: `main.js` (+ `.map`, `--enable-source-maps`), `instrumentation.js` (`--import`, optional
  OpenTelemetry), `migrations/`, `web/client` and `web/server` (self-contained SSR), production `node_modules/`. ENV:
  `NODE_ENV=production HOST=0.0.0.0 PORT=8787 WEB_DIST_DIR=/app/web MIGRATIONS_DIR=/app/migrations
  PGLITE_DATA_DIR=/data/pglite`. Code owned by root (read-only), `/data` owned by user `node` (VOLUME), HEALTHCHECK with
  `fetch` on `/api/health`.
- In production, boot fails without `IP_HASH_SALT`/`BETTER_AUTH_SECRET` or with `AUTH_SIMULATED` on. Also set
  `PUBLIC_URL`, `BETTER_AUTH_URL` and `CORS_ORIGINS` to the public origin.
- CI: `scripts/ci/smoke.sh` starts `dist/main.js` in production mode (in-memory PGlite) and checks `/api/health`, the
  SSR pages (200 with an `<h1>`) and `/robots.txt`; the `docker` job runs the same smoke test against the container.
- Target hosting (Koyeb + Neon, free tier): [`docs/engineering/architecture.md`](../../docs/engineering/architecture.md).

## Performance and observability
- **Server timing**: every response carries `Server-Timing` (`total`; rendered pages also `ssr`) and `x-cache: HIT`
  when served from the HTML cache. JSON request log (`msg: request`, `ms`, `slow`). `/api/health` pings the database
  (`select 1`, 503 if it does not answer within 2 s).
- **Tracing (optional)**: `node --import ./instrumentation.js main.js` (the image `CMD` and `pnpm start`) enables
  OpenTelemetry only with `OTEL_EXPORTER_OTLP_ENDPOINT`: one span per request (`@hono/otel`) and one per Postgres query
  (`instrumentation-pg`, only with `DATABASE_URL`; PGlite is not instrumented).
- **Real users (RUM)**: the browser measures LCP, INP, CLS, FCP and TTFB (`web-vitals`, loaded when the page is idle)
  and sends a `POST /api/vitals` beacon when the tab is hidden. The server only writes one JSON log line per metric
  (`msg: web-vital`, `path`, `rating`, `conn`): no user id, no IP, nothing in the database.
- **CI budgets**: `pnpm perf:budget` (initial JS per route ≤ 240 KB gzip, CSS ≤ 30 KB), `pnpm lint:a11y` (jsx-a11y rules
  through oxlint) and the `lighthouse` job (`lighthouserc.json`: mobile, simulated slow 4G, median of 3 runs on public
  pages; thresholds in that file). Run locally: `VITE_DATA_SOURCE=http pnpm build && pnpm perf:lighthouse`
  (`LHCI_PGLITE_DATA_DIR=.data/pglite` uses the seeded database). Accessibility tests: `apps/web/src/app/a11y.test.ts`
  (axe-core, WCAG 2.2 A/AA on the SSR HTML of every public page), `theme-contrast.test.ts` and
  `shared-ui/a11y-behavior.test.tsx`.
- **Image proxy** (`web/image-proxy.route.ts`, `GET /img/wm/<project>/<a>/<ab>/<file>/<width>`): Wikimedia Commons
  thumbnails served from our origin (the profile portrait reuses the page connection, is cached for 30 days and does
  not set the third-party `WMF-Uniq` cookie). Not an open proxy: the upstream URL is rebuilt by
  `commonsFileRef`/`commonsThumbUrl` (`@was/shared`) and only pre-rendered widths (`WIKIMEDIA_STEPS`) are accepted;
  timeout, 8 MB limit, `content-type: image/*`, byte-sized LRU, negative 404 cache for 10 min and the `imageFetch` rate
  limit for upstream fetches. The web app uses it with `VITE_DATA_SOURCE=http`; in fixture mode images come straight
  from Commons.
- **Scaling notes**:
  - Keep the server close to the database (Neon `aws-sa-east-1`): every query is a round trip.
  - CDN: `/assets` are `immutable` and precompressed and can go to a CDN as they are. **HTML cannot** yet: the CSP nonce
    is stored in the cached body, so an edge copy would repeat the same nonce for everyone. `Vary: Cookie` also
    fragments edge caches; prefer a bypass rule on cookies (`was.*`, `was_session`).
  - More than one instance: sessions and the rate limit (database store) already live in Postgres. The catalog and HTML
    caches are per process; a write on one instance does not clear the others until the TTL (HTML) or a restart
    (catalog). Next step without Redis: `NOTIFY catalog_changed` in `onWrite` and `LISTEN` on each instance (Postgres
    only). The cleanup scheduler runs on every instance and is idempotent.

## Known deviations
- One table per aggregate in `tables/*.table.ts` (table + translations), not one file per table.
- No `change_requests` table yet: admin proposals are `field_conflicts` + `ai_extraction_queue` (+ AI-extracted values in
  `field_provenance`).
- `legal_acceptances(document_kind, version)` instead of `user_consents.document_id` (legal texts live in shared);
  `user_consents` stores the optional purposes.
- Counters (likes, replies, user votes) bump `version` but create no snapshot or audit entry (derived data).
- HTML cache only for anonymous visitors; the nonce stays fixed while a page is cached. There is no per-URL CDN purge.
