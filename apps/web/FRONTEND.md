# apps/web: guide for building screens

The foundation is in place: API contracts in `@was/shared`, **one** endpoint factory, fixtures generated from the
prototype, a component kit, a simulated session and routes for every screen. Your job: fill
`src/modules/<module>/`. Before creating anything, search here first.

Code conventions (source of truth): [`docs/engineering/conventions.md`](../../docs/engineering/conventions.md).
Package map: [`docs/engineering/architecture.md`](../../docs/engineering/architecture.md). Tools:
[`docs/engineering/tooling.md`](../../docs/engineering/tooling.md). Visual and behavioural reference (gitignored):
`plan/front-prototype/pages/*`.

## Folders
```
packages/shared/src/            single source (server + web): enums · consts · Zod schemas · contracts (method + path + schemas) · pure helpers (+ tests)
apps/web/src/
  app/                          SSR: entry-server.tsx / entry-client.tsx, create-router.tsx (router + QueryClient per request),
                                router.tsx (every route, lazy per page, loaders + head), root-document.component.tsx (the <html>),
                                root-layout.component.tsx, request-scope.ts (page boot), route-prefetch.helper.ts, head.helper.ts, styles.css
  data/                         generic data layer
    define-endpoint.helper.ts   defineQuery / defineMutation (replaces service + adapter + hook)
    endpoints/*.query.ts        ONE definition per endpoint (fixture included)
    fixtures/*.fixture.ts       fixture logic that needs rules (home, comments, votes, me, admin…)
    demo.store.ts               demo mutations (memory + localStorage)
    fixture-mode.store.ts       ?fixture=sample|empty|loading|error (default sample; cookie was_fixture)
  fixtures/sample/*.json        GENERATED by `pnpm fixtures:export` (do not edit by hand)
  i18n/                         useText, useFormat, useLocalized, locale store, catalog coverage test
  session/                      useSession() (kind/user from sessionQuery), requireLogin(), signOut(), auth-client (Better Auth, Google), consent dialog; simulated profiles in dev
  shared-ui/                    generic UI components, hooks and helpers
  modules/<module>/             module pages and components (+ <module>.const.ts with its texts)
```

## Data
### Using an endpoint
```tsx
import { athletesQuery } from '@/data/endpoints/athletes.query';
const q = athletesQuery.useQuery({ query: filters });            // typed input/output from the shared contract
const v = tierVotesQuery.useQuery({ params: { slug } }, { enabled: isSignedIn });
await athleteProfileQuery.fetch({ params: { slug } });           // prefetch / loader
const post = postComment.useMutation({ onSuccess: … });           // invalidates related queries automatically
post.mutate({ params: { slug }, body: { body, parentId } });      // errors: ApiError (status + body { error, message, errors })
```

Every response is validated by the contract schema (`contract.response.parse`): a mismatch fails loudly. Source:
fixtures (default) or the real API with `VITE_DATA_SOURCE=http` (`pnpm dev:api`; same origin: `apps/server` serves pages
and `/api` on :8787; during SSR the call is in process, `app.fetch`; `VITE_API_BASE_URL` is optional). In http mode
the simulated session goes in the `x-was-session` header. Rules and compositions used by the fixtures (`composeHome`,
`buildCommentThreads`, `composeCompare`, `accessDenial`, `adminPendingCounts`, `officialTierChangeError`,
`reviewDossierOutcome`) are the same ones the server uses (`@was/shared`).

### Adding an endpoint
1. `packages/shared/src/schemas/<subject>.schema.ts`: Zod schemas (types from `z.infer` go in a `*.type.ts`).
2. Contract in `packages/shared/src/contracts/*.contract.ts`:
   `defineContract({ method, path: '/api/...', access, params?, query?, body?, response, summary })`.
3. If it needs new prototype data: add the file to `scripts/fixtures/export-prototype-fixtures.mjs` (with its schema)
   and the type to `data/sample-fixtures.type.ts`; run `pnpm fixtures:export`.
4. `data/endpoints/<domain>.query.ts`:
   `export const xQuery = defineQuery(Contract, { sample: ({ input, sample, session }) => …, empty?: 'not-found' | fn })`.
   Mutation: `defineMutation(Contract, handler, { invalidates: [xQuery] })`, writing to `demoStore`.

The **empty** mode is derived from the schema (`emptyOf`); pass `empty` only when emptiness depends on the input or the
entity does not exist (404). A test enforces this (`data/empty-response.helper.test.ts`).

### Modes (dev)
`?fixture=sample` (default) · `empty` (empty database) · `loading` (never resolves) · `error` (503). They persist per
tab; a discreet switcher sits in the bottom-left corner (dev only). `?as=anon|reader|admin` forces the session.

## Building a page
```tsx
const route = getRouteApi('/sports/$slug');
export function SportPage() {
  const { slug } = route.useParams();
  const { filters, setFilter, reset, activeCount } = useUrlFilters(SportPageFiltersSchema); // filters in the URL
  const sport = sportPageQuery.useQuery({ params: { slug } });
  const t = useText(SPORTS_MESSAGES);
  return (
    <QueryBoundary query={sport} loading={<SkeletonList rows={6} />}>
      {(s) => (
        <PageLayout title={s.name} eyebrow={t.eyebrow} breadcrumb={[{ label: t.sports, link: { to: '/sports' } }, { label: s.name }]} aside={…}>
          <Section title={t.champions}><AthleteGrid athletes={…} emptyTitle={t.noChampions} /></Section>
        </PageLayout>
      )}
    </QueryBoundary>
  );
}
```
Pages live in `modules/<module>/<name>.page.tsx`; the route is registered in `app/router.tsx` (search params typed by
the `@was/shared` schemas). Replace a module's `StubPage` with the real page.

## SSR
Every page is rendered by `apps/server` (Hono) with TanStack Router SSR (streaming) and hydrated in the browser. One
port: http://localhost:8787 (`pnpm dev` with fixtures, `pnpm dev:api` with the API; Vite runs as middleware inside the
server, with HMR).
- **Loaders only prefetch** and return the `PageMeta` for `<head>`:
  `prefetchQueries(context.queryClient, [xQuery.queryOptions(input)])`; the main entity uses `ensureOr404` (404 →
  `notFound()`, HTTP 404). Never wait for `?fixture=loading`; fixtures have no latency on the server.
- **The loader and the page build the query key with the same helper** (`home-query.helper.ts`,
  `athletes-query.helper.ts`, `sports-query.helper.ts`): if they differ, hydration shows a skeleton or an error. A new
  public page = loader + input helper + `head`.
- **No `window`/`document`/`localStorage`/`new Date()` during render.** "Today" is `useToday()`
  (`app/use-boot.hook.ts`, server `APP_TIME_ZONE`); instants with time use `instantFormat()`
  (`shared-ui/format.helper.ts`). Effects (`useEffect`) may use the browser.
- State the server must know lives in cookies: `was_fixture`, `was_session`, `was-theme`, `was_locale` (`<html
  data-theme>` is already right, no inline script). Read in the boot (`app/request-scope.ts`): `AsyncLocalStorage` on
  the server, a module on the client.
- Browser-only components: `<ClientOnly fallback={box of the same size}>` (TanStack Router; the globe).
  `ChartContainer` already draws only in an effect.
- CSP with a per-request nonce: inline scripts only with `nonce` (the router and React already add it).
- **Head**: the loader returns `PageMeta` (`title`, `description`, `image` → og:image, `noindex`, `jsonLd`). JSON-LD only
  through the `@was/shared` helpers (`webSiteJsonLd`, `organizationJsonLd`, `athleteJsonLd`, `sportJsonLd`,
  `breadcrumbJsonLd`, `itemListJsonLd`), emitted in `<script type="application/ld+json" nonce>`. 404 and error pages get
  their own title + `noindex` on the root route.
- **New page**: `lazyPage('<module>/<file>', 'ExportName')` in `app/router.tsx` (records the module in
  `staticData.pageModule`: the server adds a `modulepreload` for the route chunk).
- Test: `src/app/entry-server.test.ts` (200 + `<h1>` + dehydrated state + nonce; 404 with title; valid JSON-LD; chunk
  preload).

## Languages (pt-BR, en, es on the same URL)
The translation switches **in place**: the switcher (`LanguageSwitcher`, header) writes the `was_locale` cookie (1
year), changes `<html lang>`, re-renders and calls `router.invalidate()` (titles from `head()` and API data in the new
language). The URL does not change. SSR resolves cookie → Accept-Language → pt-BR into `boot.locale`.
- **Catalogs are the only place for pt-BR/es text.** `x.const.ts` holds the pt-BR object (`X_TEXT`, the source) and
  exports `X_MESSAGES = defineMessages(X_TEXT, { en: X_TEXT_EN, es: X_TEXT_ES })`; next to it, `x.const.en.ts` and
  `x.const.es.ts` use `satisfies Messages<typeof X_TEXT>` (same keys, same signatures). Routes and data stay **out** of
  the dictionary (`NAV_ITEMS = [{ to, labelKey }]`). Keys, identifiers and URL values are English.
- **Component**: `const t = useText(HOME_MESSAGES).intro` (`@/i18n/use-text.hook`). Outside components (helper called
  during render, loader/head): `currentText(X_MESSAGES)` (`i18n/text-for.helper.ts`). Long documents (legal, "how we
  choose"): a per-language map read with `useLocalized(LEGAL_DOCS)` / `currentLocalized`.
- **Formatting**: `useFormat()` (date, day and month, month, number, %, range, "3 days ago", plural, collator
  `fmt.compare`, country, language) with `APP_TIME_ZONE`; `formatDate` / `instantFormat` / `formatRelativeDay` read the
  current language. No hard-coded `'pt-BR'` and no `localeCompare` without the collator.
- `useMemo` / `useCallback` that use texts must list `t` in their dependencies (the response may be the same reference
  in another language).
- **Data**: the query key ends with the locale; switching language keeps the previous response until the new one
  arrives (no skeleton). The http client sends `x-was-locale`. Detail responses carry `contentLocale`;
  `PageLayout contentLocale={…}` shows the `UntranslatedNote` when it differs from the UI language. Fixtures say
  `contentLocale: 'pt-BR'`.
- **Test**: `src/i18n/messages-coverage.test.ts` (every `*_MESSAGES`: same keys, arity, no empty string, en/es
  translated; documents with the same structure).

## Session and participation
Real sign-in = Google through Better Auth (cookie `was.session_token`, same domain). `useSession()` reads `kind`/`user`
from `sessionQuery` (already present in SSR). `pendingConsent` opens the blocking consent dialog (Terms + Privacy with
versions, 18+; "decline and sign out"). `signOut()` ends the Better Auth session, clears the simulated profile and
refetches queries. The simulated profile switcher (and the `x-was-session` header) exists only with fixtures or with
`AUTH_SIMULATED` on the server (`session.simulated`).

`const { isSignedIn, isAdmin, user, requireLogin } = useSession();` → before voting, commenting, replying or liking:
`if (!requireLogin('vote')) return;` (opens the dialog). `tierVotesQuery` requires an account (use
`enabled: isSignedIn`; visitors see only the official tier and the 4 buttons). Demo mutations go to `demoStore` (memory
+ localStorage; SSR does not see them, and the client invalidates queries after hydration if anything is stored). The
session menu has an entry that clears the demo data.

## Rules
- **Never** redefine something from the kit. Need a generic variation? Extend the component in `shared-ui` (with props);
  do not copy it.
- Generic (used by 2+ modules) → `shared-ui`. Specific → `modules/<module>`. Enums, consts shared with the server,
  schemas and business rules → **only** `packages/shared`.
- One declaration kind per file, with its suffix (`.page.tsx`, `.component.tsx`, `.hook.ts`, `.helper.ts`, `.const.ts`,
  `.interface.ts`, `.type.ts`, `.query.ts`, `.store.ts`, `.fixture.ts`…); see
  [conventions.md](../../docs/engineering/conventions.md). Direct imports (no barrels in the app).
- UI text only in `<module>.const.ts` (or `ui-text.const.ts` / `domain-labels.const.ts`) with `.en.ts` / `.es.ts`
  siblings, read through `useText`. No loose visible string in JSX.
- Colours only through tokens (`var(--…)`, `tokenColor('c-teal')`). **No hex** in module components or CSS; new tokens go
  to `packages/shared/src/theme/theme.css` (light and dark).
- Filters and tabs live in the URL (`useUrlFilters`), never in loose state.
- Accessibility (WCAG 2.2 AA): one `h1` per page (PageLayout); decorative icons `aria-hidden`; buttons without text get
  `aria-label`; visible focus; form errors through `FormField` (aria-describedby) and focus on the first invalid field;
  no horizontal scroll at 375 px; respect `prefers-reduced-motion`.
- Images by link only, `referrerPolicy="no-referrer"`, `loading="lazy"`.
- Check: `pnpm test`, `pnpm typecheck`, `pnpm --filter web build`, light/dark, `?fixture=empty|loading|error`, console
  without hydration errors.
